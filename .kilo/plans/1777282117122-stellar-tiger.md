# Plan: Desktop Welcome Screen

## Problem
The current `Landing.tsx` is a full marketing website (hero, features, AI demo, pricing, CTA, footer) shared between web and desktop. In the Tauri desktop app, users see this long-scroll marketing page before signing in — it feels foreign to a native desktop experience, like opening Slack and seeing a website instead of a login window.

## Approach: Split-Panel Welcome Screen with Auth
Create a new `DesktopWelcome.tsx` component that replaces the marketing landing page when running inside Tauri. It uses a **split-screen layout**:
- **Left panel** (branding): Logo, tagline, 3-4 key value props with icons, subtle animated background — establishes trust and communicates value concisely
- **Right panel** (auth form): Sign In / Sign Up toggle with the same Clerk-based auth logic currently in `Login.tsx` and `Signup.tsx`

This mirrors the desktop-app convention used by Slack, Discord, Figma, VS Code (with settings sync), etc.

## Implementation Plan

### 1. Create `src/pages/DesktopWelcome.tsx`
- New component with a split-panel layout (left: branding, right: auth)
- **Left panel** content:
  - Selah logo + brand name
  - Tagline: "Every word. Every verse. Every moment."
  - 3-4 benefit cards with icons (e.g., AI Scripture Detection, Offline-First, Multi-Screen Projection, Drag-and-Drop Dashboard)
  - Subtle animated gradient/blob background matching the app's design language (teal/amber accents)
- **Right panel** content:
  - Tab toggle: Sign In / Sign Up
  - Sign In form (email + password + Google OAuth) — reused logic from `Login.tsx`
  - Sign Up form (name, email, password + Google OAuth) — reused logic from `Signup.tsx`
  - Church setup step included inline in the sign-up flow (same multi-step flow as `Signup.tsx`)
- Design tokens: reuse the same CSS variables (`--text-primary`, `--bg-card`, etc.), gradient accents (`#0d9488`, `#0f766e`), and `Crimson Pro` font for headlines
- Desktop-native touches:
  - No hamburger menu navbar (no need on desktop)
  - Window drag region on the left panel (or a custom titlebar hint)
  - Subtle window controls area integrated at top

### 2. Create shared auth logic hook `src/hooks/useAuth.ts`
- Extract the sign-in and sign-up Clerk logic from `Login.tsx` and `Signup.tsx` into a reusable hook
- This avoids duplication between the web auth pages and the new desktop welcome screen
- Hook handles: `useSignIn`, `useSignUp`, email/password submission, Google OAuth redirect, verification, and Convex user upsert

### 3. Update routing in `src/App.tsx`
- Import `isDesktop` from `src/platform/index.ts`
- Conditionally render `DesktopWelcome` instead of `Landing` for the `/` route when `SignedOut` and running in Tauri
- Keep the `/landing` route pointing to `Landing.tsx` unchanged (for web/SEO)
- The `/login` and `/signup` routes remain unchanged (they work fine in both contexts, but desktop users won't need them as standalone pages)

### 4. Key Design Decisions
- **Left panel** has a fixed width (~45%) with gradient background; right panel fills the rest
- **Mobile responsive**: On narrow desktop windows (below ~768px), collapse to a single-column centered auth form with simplified branding above
- **Dark mode**: Both panels respect the app's dark theme
- **No scroll**: The entire view fits in the viewport — no scrolling needed (desktop screens are tall enough)
- **Church setup**: After sign-up verification, the church setup step is shown in the same right panel (inline), avoiding a redirect to `ChurchSetup.tsx`
